# 角色书库 · Card Library

用于 SillyTavern / TauriTavern 的角色卡管理前端扩展。无需切换当前聊天，即可搜索和试读卡片、整理独立分组，再决定打开、编辑或删除。

版本：**0.4.0**。纯 ES 模块，无构建依赖，不需要酒馆助手或额外后端服务。

## 功能

- **全文搜索**：角色名、人设、性格、场景、主开场、备用开场、作者备注、对话示例、系统提示、卡片标签与内嵌世界书。支持多关键词同时匹配和双引号短语；可限定搜索范围。结果中的名称、作者、摘录和标签高亮匹配词，支持大小写 / 全半角归一化，清空搜索即恢复。
- **卡片标签**：列表直接显示已保存的 AI 分类和卡片自带标签，标明来源；点击任一标签筛选全库同类型角色，可一键清除，也可继续叠加关键词或分组。AI 结果保存后立即更新。最多两行，键盘进入标签区时展开，没有标签则不占位置。只读取已有数据，不写回角色卡，也不会因展示或筛选再调用模型。
- **缓存与分批索引**：每批 24 张、最多 3 张并发，边读取边浏览；同一酒馆页面内重开书库复用卡片、关联世界书与开场摘录。关闭会停止未完成的索引，重开接着补齐；单张失败不影响其余卡片，重试只补读失败内容。
- **关联世界书**：预览主世界书和额外关联书；勾选「含关联世界书」后也进入全文索引。
- **独立分组**：一张卡可加入多个组；新建、改名、移出与删除组；分组完全保存在本扩展设置，不修改酒馆原生标签。
- **收藏与批量整理**：选择本页、全选搜索结果、批量分组、收藏、删除。卡片网格 / 列表切换、名称 / 最近聊天 / 最近添加排序。
- **试读**：人设、开场白、世界书、聊天四个页签。开场白使用正在预览角色的已启用正则，显示 Markdown 与 HTML / CSS 静态界面，可切换原文；备用开场切换不改聊天首条消息。
- **快速编辑**：名称、人设、性格、场景、主开场白、对话示例、作者备注。只合并更改字段；保存前检查这些字段是否已被其他操作修改；保留未知扩展字段。
- **删除**：列出全部目标卡，输入数量确认；默认保留聊天。通过宿主删除流程同步角色列表和原生状态，逐个核对结果。
- **聊天预览**：浏览已保存的角色聊天并搜索整篇正文；每次呈现 60 条，可显示更早消息，不切换当前聊天。
- **AI 概括**：可复用酒馆当前 API，也可单独配置 OpenAI 兼容 API。先展示将发送的卡片资料，生成成功自动保存概括与类型；生成中关闭弹窗或书库，完成后仍保存（需保持酒馆页面打开）。重新打开可查看已有结果，修改后保存或按类型分组。不会发送聊天记录。
- **额外 API**：配置地址、密钥和模型，支持拉取模型列表、下拉选择与手填。密钥由酒馆密钥库保存，已有原生活动密钥会恢复，生成明确指定本配置的密钥 ID。
- **内置 OpenCode Go 适配**：额外 API 识别官方 Go / 按量 Chat Completions 地址，自动添加稳定会话头与真实客户端标识，修正模型目录地址；不自动更改计费路径，无需另装 OpenCode Go 连接助手。
- **整理数据迁移**：导出 / 合并导入分组、收藏和 AI 概括。导出经过宿主下载函数，TT 使用其原生保存流程。
- **手机与键盘**：手机只固定标题，搜索、分组和分页随列表滚动；筛选与排序集中在弹窗，多选才显示底部单行操作区。详情标题保留返回按钮。44px 操作区，固定保存区；`/` 聚焦搜索，`Esc` 关闭当前弹层，页签可用方向键切换。
- **外观**：参考 AO3 的酒红导航、衬线标题、下划线阅读入口、细边框和紧凑作品条目；浅色灰白，深色炭灰与浅红，也可跟随酒馆明暗。所有下拉框与折叠条目都有明确指示。

## 安装

在 ST 或 TT 的「扩展 → 安装扩展」中粘贴仓库地址：

```text
https://github.com/demilich1117/SillyTavern-Card-Library
```

安装后刷新酒馆，TT 可重启应用。后续在扩展管理中检查更新。

此前使用 ZIP 安装且目录中没有 `.git` 时，可先移走旧的同名扩展目录，再通过仓库地址安装；分组、收藏与 AI 概括保存在酒馆设置中。也可继续使用下方 ZIP 覆盖方式。不要同时保留两份已启用的书库扩展。

### SillyTavern

1. 解压 `SillyTavern-Card-Library-v0.4.0.zip`。
2. 将其中整个 `SillyTavern-Card-Library` 文件夹放入酒馆的 `data/<用户>/extensions/`。单用户通常是 `data/default-user/extensions/`。
3. 最终路径应为 `data/default-user/extensions/SillyTavern-Card-Library/manifest.json`，不要多套一层目录。
4. 刷新酒馆，在扩展列表确认已启用「角色书库 · Card Library」。

开发时也可放在 `public/scripts/extensions/third-party/SillyTavern-Card-Library/`。不要把整个 `sillytavern-plugins` 工作区作为扩展安装。

从旧版更新时，用新包内的同名文件夹覆盖原扩展文件，刷新酒馆即可；整理数据保存在酒馆设置中，不在扩展目录内。

### TauriTavern

将同一个扩展文件夹放进 TT 所配置数据根目录的 `default-user/extensions/`，或全局目录 `extensions/third-party/`，然后重启 TT。这里的数据根是 TT 实际设置的位置，不是固定磁盘路径。local 与 global 同名时 local 优先。

手机上优先在 TT 的「安装扩展」中填写上方 GitHub 地址。使用 ZIP 时，需要通过 TT 可用的数据目录导入 / 文件管理方式放到上述位置；不要把 ZIP 文件路径填入 Git 地址栏。

### 打开入口

- 输入框旁的魔术棒扩展菜单 → 单色书本图标 **角色书库**，沿用酒馆原生菜单样式。
- 扩展设置 → **打开角色书库**。
- 输入斜杠命令 `/card-library`。

## 常用操作

**找卡**：选择「全部角色」后输入关键词。索引完成前显示读取进度；失败会提示结果可能不完整，并提供重试。关键词可分别出现在不同字段中。

**按标签找同类**：点击卡片上的标签或 AI 类型，会回到全部角色并清除旧关键词，显示名称完全匹配的同标签角色（忽略大小写 / 全半角与首尾空格）。顶部显示当前标签，点「清除标签筛选」恢复普通浏览；随后输入关键词或选择分组可进一步缩小结果。

**重新打开 / 刷新**：关掉书库再打开，会检查变更并复用当前页面的缓存。角色编辑和世界书更新按宿主事件更新相关内容；搜索框旁的刷新按钮则强制重读全部卡片。加载中可关闭，已完成的缓存保留；失败提示中的「重试读取」只补齐失败内容。

**整理**：桌面勾选卡片 → 分组 → 勾选目标组 → 应用。手机先点「多选」，勾选后在底部「批量操作」中选择分组、收藏、删除或全选结果；点「取消多选」恢复浏览。横线表示这批卡片中只有部分已归组；未动的分组保持原状。手机的分组新建和管理在「筛选」内。

**手机筛选**：「筛选」中调整搜索内容范围、关联世界书、排序和卡片 / 紧凑列表；点「应用」生效。「重置筛选」恢复范围、关联世界书和排序默认值。

**试读**：点击角色标题、卡片或「阅读」进入详情。手机正文和角色信息一起滚动，标题栏左侧随时返回书库。只有点击「开始聊天」才切换宿主角色。

**编辑**：详情右上角笔形按钮。名称修改不改 PNG 文件名；独立分组仍按文件身份绑定。快速编辑不提供世界书写入、备用开场编辑或高级扩展字段编辑，这些可继续使用酒馆原生编辑器。

**AI 分类**：使用酒馆当前连接或在书库设置中配置额外 API，再点详情中的「AI 概括」。较长字段会截取，页面会明确提示。成功结果自动保存；关闭书库后仍会保存完成结果，但需要保持酒馆页面打开。使用当前连接时遵循宿主生成设置及已安装钩子。

## 数据与边界

- 独立分组、收藏、外观和 AI 概括保存在 `extensionSettings.card_library`。不写入角色卡的标签或可分享的扩展字段。
- 索引缓存仅保存在当前酒馆页面内存中，不写入整理数据；刷新页面、重启 ST / TT 或重新加载扩展后需重建。外部直接修改文件且宿主未发变更事件时，使用手动刷新同步。
- 分批处理降低瞬时请求和正文处理压力，没有对整个卡库设置统一超时。单请求仍有 60 秒超时；网络中断、宿主负载或单张超大卡片仍可能失败，已成功内容保留并可重试。
- 文件名是身份；同名角色不会合并。宿主发出重命名事件时迁移整理数据。外部手动改名、换数据目录或跨设备迁移需保留文件名，并导出 / 导入整理数据。
- 整理数据 JSON **不包含角色卡本体或聊天备份**。分组删除只移除关系；角色删除无法在本扩展撤销。
- 角色删除由宿主处理，会关闭当前聊天；有生成进行时本扩展拒绝编辑、删除或切换。
- 人设、世界书、聊天保持文本预览。开场白按全局 → 当前预设 → 目标卡的已启用局部正则顺序，执行存储处理与深度 0 的显示处理，再净化为隔离的静态 HTML / CSS 预览。不会误用当前聊天角色的局部规则；未批准的卡片正则保持禁用并显示提示。
- 开场预览支持角色、用户、人设等静态宏；聊天变量宏保留原样，不运行宏的写变量操作、助手脚本或 JavaScript。依赖脚本初始化的前端可能没有完整画面，交互功能请进入聊天使用；原文始终可查看和编辑。
- 额外 API 配置只保存地址、模型和密钥引用；导出整理数据不包含连接配置或密钥。拉取模型会先把新密钥存入酒馆密钥库，取消弹窗不会删除已存密钥；原生密钥管理可维护这些条目。首次创建自定义密钥时，宿主会把它列为该类型的活动密钥；已有活动密钥时会恢复原选择。
- 聊天预览展示已保存的单角色历史，不含当前尚未保存的编辑，不含群聊，不会预取所有聊天作为全库索引。
- ST 的兼容聊天读取接口一次读取整篇历史，界面分批呈现；非常大的聊天文件仍有首次读取成本。
- 所有写入都检查 HTTP 状态。编辑有字段级冲突检查，但宿主没有提供原子 compare-and-swap；极短的跨客户端并发写入窗口仍受宿主限制。

## 配置额外 API / OpenCode Go

书库右上角「设置」→「配置 AI / 额外 API」，或在「AI 概括」窗口直接打开配置。选择「使用额外 API」，填入基础地址与 API Key，点击「拉取模型」，选择模型后保存。拉取失败时可手填模型名称。

使用 OpenCode Go 时点击「填入 OpenCode Go 地址」，填入自己的密钥，再拉取并选择套餐支持的模型。内置适配只作用于书库的额外 API；主聊天、其他扩展与「使用酒馆当前 API」仍由原宿主连接流程处理。公共模型目录不等于账号可用模型清单，账号权限、额度或模型不支持的问题不会被适配器消除。

实现参考用户已有的 OpenCode Go 连接助手 0.2.0，并依照 [官方会话与端点说明](https://opencode.ai/v2/docs/console/harnesses) 和 [公共模型目录说明](https://opencode.ai/v2/docs/console/api/inference) 核验；MIT 署名与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。不修改其他插件，也不安装全局请求拦截。

## 开发

```text
npm test
npm run check
npm run prepare-demo
npm run demo
npm run package
```

`prepare-demo` 从本机 `http://127.0.0.1:8000/lib.js` 复制同版本渲染依赖到被忽略的测试目录；也可用 `node dev/prepare-demo.mjs http://你的测试酒馆地址` 指定来源。`demo` 默认监听 `http://127.0.0.1:18787`，可用 `CARD_LIBRARY_PORT` 改端口，仅使用虚构数据。`package` 使用 Python 标准库，按白名单打包并逐文件验证；不会包含测试示例、下载的上游源码、浏览器记录或用户数据。

`dev/browser-smoke.js` 与 `dev/browser-mobile.js` 是 Playwright CLI `run-code` 脚本，使用演示服务；第二个脚本的地址为本次验证端口 18788。不要在真实酒馆运行这些带编辑 / 删除的模拟测试脚本。

0.3.0 视觉参考 [AO3 公开页面截图](https://commons.wikimedia.org/wiki/File:Ao3-screenshot.png)，采用酒红、灰白、衬线标题和传统表单控件；深色为本扩展自行适配。分组 / 预览布局沿用早期参考 Eagle 的组织方式。具体设计记录在 [DESIGN.md](DESIGN.md)，未复制第三方 Logo、代码或图片资产。
